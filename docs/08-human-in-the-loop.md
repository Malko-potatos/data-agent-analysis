# 08. Human In The Loop

데이터 분석과 자동화 agent는 모든 것을 혼자 끝내는 시스템이 아니다. 사람에게 넘겨야 하는 판단, 승인, 위험 경계가 명확할수록 더 안정적으로 작동한다.

## Human Roles

| 역할 | 책임 |
|---|---|
| Request Owner | 목적, 결과물, 우선순위 결정 |
| Data Owner | 데이터 정의, 권한, 민감정보 판단 |
| Domain Reviewer | metric 정의와 업무 규칙 검토 |
| Approver | 외부 발송, 삭제, 배포, 권한 변경 승인 |
| Operator | 반복 실행 결과와 실패 로그 확인 |

## Ask Instead Of Guessing

다음은 추정하지 않고 질문한다.

- metric 정의가 업무마다 다를 때
- 결측치를 어떻게 처리할지 모를 때
- 환불, 취소, 중복 계정처럼 매출에 영향을 주는 규칙이 불명확할 때
- 민감정보가 포함된 데이터 사용 범위가 애매할 때
- 외부 action 실행 여부가 불분명할 때

## Reviewable Outputs

사람이 검토할 수 있는 산출물은 다음을 포함한다.

- 짧은 executive summary
- 사용한 입력과 기간/필터
- 핵심 표와 차트
- 계산식과 제외 조건
- 검증 결과
- 확인 필요 사항
- 권장 action과 승인 필요 action

## Approval Requests

승인 요청은 구체적이어야 한다.

나쁜 예:

```text
결과를 보내도 될까요?
```

좋은 예:

```text
다음 이메일 초안을 김OO에게 발송하려 합니다.
수신자: kim@example.com
제목: 6월 마케팅 성과 요약
본문: ...
첨부: marketing-report-2026-06.pdf
승인하면 발송하고, 승인하지 않으면 draft로 남기겠습니다.
```

## Failure Recovery

자동화가 실패하면 다음 정보를 남긴다.

- 실패 시각
- 실패 단계
- 입력 데이터 범위
- 마지막 성공 상태
- 재시도 여부
- 사람이 처리해야 할 항목

실패한 자동화가 조용히 계속 실행되는 것보다, 멈추고 검토 가능한 기록을 남기는 편이 낫다.
