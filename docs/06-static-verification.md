# 06. Static Verification

정적 검증 기준은 프롬프트 끝에 붙는 문장이 아니다. 작업 harness와 분리된 별도 계층이다.

에이전트가 "맞는 것 같다"고 말해도 검증이 끝난 것은 아니다. 어떤 입력을 썼고, 어떤 계산식을 적용했고, 어떤 기준과 대조했는지가 남아야 한다.

## Verification Table

| 검증 항목 | 질문 |
|---|---|
| 입력 경계 | 어떤 파일, DB, API, 화면, 문서를 사용했는가? |
| 기간/필터 | 분석 기간과 필터가 명시됐는가? |
| 원본 보존 | raw data나 기존 코드를 임의로 바꾸지 않았는가? |
| 계산 근거 | 지표 정의, 계산식, 분모/분자, 제외 조건이 명시됐는가? |
| 조인 검증 | join key, match rate, unmatched row, 중복 여부를 확인했는가? |
| 샘플 검산 | 샘플 row를 수동 계산해 결과와 비교했는가? |
| 해석 분리 | 확인한 사실, 추정, 사람이 판단할 내용을 분리했는가? |
| 승인 경계 | 발송, 삭제, 배포, 권한 변경을 승인 없이 하지 않았는가? |
| 산출물 품질 | 사람이 리뷰 가능한 형태로 남겼는가? |

## Evidence Levels

| Level | Meaning | Example |
|---|---|---|
| L0 | 주장만 있음 | "분석했습니다" |
| L1 | 사용한 입력을 밝힘 | 파일명, 기간, 필터 |
| L2 | 계산식과 검증 일부 포함 | row count, total, sample check |
| L3 | 대조 기준 포함 | 기존 dashboard/export와 비교 |
| L4 | 반복 실행 가능 | query, script, template, automation 로그 포함 |

수업에서는 L2를 최소 기준으로 삼고, 운영 자동화는 L3 이상을 목표로 한다.

## Approval Boundary

다음 action은 검증과 별개로 사람 승인이 필요하다.

- 이메일, Slack, DM, 게시글 발송
- 파일 삭제 또는 원본 덮어쓰기
- DB write, schema 변경, 권한 변경
- 외부 서비스 배포
- 비용이 발생하는 API 호출 또는 캠페인 변경
- 민감정보가 포함된 데이터 외부 반출

## Verification Prompt Block

실행 프롬프트 끝에는 다음 블록을 붙인다.

```text
검증:
- 사용한 입력과 기간/필터를 먼저 기록하세요.
- row count, total/subtotal, join match rate를 확인하세요.
- 샘플 row 3개 이상을 수동 검산하거나 계산식을 설명하세요.
- 확인한 사실, 추정, 사람 확인 필요 사항을 분리하세요.
- 발송/삭제/배포/DB 변경은 실행하지 말고 승인 요청으로 남기세요.
```
